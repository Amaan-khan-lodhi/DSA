2. IF GIT OPENS AN EDITOR (VIM) INSTEAD OF THE PROMPT
------------------------------------------------------
Sometimes after `git commit`, `git pull`, or `git merge`, a black screen
appears with text like "-- INSERT --" or ".git/MERGE_MSG" at the bottom.
This is normal — Git opened Vim so you can write/edit a commit message.
It is NOT an error and NOT a place to type shell commands.

If it happens:
1. Press Esc (leaves typing/insert mode).
2. Type :wq then Enter — saves the message and finishes the commit.
   (Or type :q! then Enter to cancel WITHOUT saving, if you want out.)

If you typed something wrong before pressing Esc:
- Move to that line, press Esc first, then press dd to delete the whole
  line (repeat dd for each extra line), then :wq to save and exit.

To stop this from happening for commits (optional, one-time setup):
git config --global core.editor "nano"
(or use a GUI editor like VS Code:)
git config --global core.editor "code --wait"

To skip the editor entirely on a merge and accept the default message:
git merge --no-edit

8. PULL CHANGES FROM GITHUB
---------------------------

If Git says:
"Updates were rejected because the remote contains work that you do not have locally"

Use:

Then:
git push

If there is a conflict, STOP and inspect the conflict before using force push.

Note: a plain `git pull` can trigger a merge and open Vim for a merge
commit message (see Section 2) — that's expected, not a bug.

11. UNTRACK / REMOVE FILES
--------------------------
Remove a file from Git and your computer:
git rm "filename"

Remove a file from Git but KEEP it on your computer:
git rm --cached "filename"

Remove a folder from Git but KEEP it locally:
git rm --cached -r foldername


12. UNDO / RESTORE
------------------
Discard changes to one file:
git restore "filename"

Unstage a file:
git restore --staged "filename"

IMPORTANT:
git restore can permanently discard uncommitted changes.


13. GITIGNORE
------------
For C++ projects, a .gitignore can prevent compiled files from being uploaded.

Example:

Create it:
echo "*.exe" >> .gitignore

Then:
git add .gitignore
git commit -m "Add gitignore"
git push

You can also add:
.vscode/
*.exe
*.obj
*.o

17. IF PUSH SAYS 403 / WRONG GITHUB ACCOUNT
--------------------------------------------
Example:
Permission to Amaan-khan-lodhi/DSA.git denied to saifkhandev.

This means GitHub authentication is using the wrong account.

On Windows:
1. Open Credential Manager.
2. Open Windows Credentials.
3. Remove the saved GitHub credential.
4. Run:
   git push
5. Sign in with the correct GitHub account.

Check Git author identity:
git config --global user.name
git config --global user.email

Change them if needed:
git config --global user.name "Amaan Khan Lodhi"
git config --global user.email "YOUR_GITHUB_EMAIL"

NOTE:
Changing user.name/user.email does NOT by itself change the GitHub account used for HTTPS authentication.


18. COMMON PUSH ERROR: "FETCH FIRST"
------------------------------------
If:
git push

says:
"rejected (fetch first)"
or:
"remote contains work that you do not have locally"

Run:
git status
git pull --rebase origin main
git push

If conflicts appear:
STOP and resolve the conflict before continuing.

Do NOT use:
git push --force

unless you deliberately understand that it can overwrite remote history.


19. MERGE / REBASE CONFLICTS AND HOW TO BACK OUT
--------------------------------------------------
If a rebase reports conflicts:

git status

Open the conflicted file(s), resolve the conflict, then:

git add .
git rebase --continue

After the rebase finishes:
git push

If you want to cancel the rebase:
git rebase --abort

If a plain merge (not rebase) reports conflicts, resolve them the same
way, then:
git add .
git commit

If you want to cancel a merge instead of finishing it:
git merge --abort
